# Upwork AI Assistant

ИИ-ассистент для мониторинга биржи [Upwork.com](https://www.upwork.com/): собирает новые вакансии, отсеивает нерелевантные по настраиваемым фильтрам, оценивает оставшиеся с помощью LLM, пишет персонализированный черновик отклика и присылает его в Telegram.

## Что он делает

1. **Планировщик** раз в ~10 минут (с джиттером) открывает сохранённый поиск Upwork в браузере под вашей сессией.
2. **Сборщик** достаёт список вакансий из embedded-состояния страницы поиска (Nuxt SSR, `window.__NUXT__`) — на странице поиска нет отдельного JSON-эндпоинта под список вакансий. Парсинг DOM остаётся резервным путём (пока не реализован предметно).
3. **Фильтры** отсеивают вакансии по бюджету, типу оплаты, стране и верификации заказчика, числу откликов, ключевым словам и чёрному списку.
4. **Скоринг** — дешёвая модель оценивает релевантность 0–10 по вашему профилю.
5. **Генерация** — сильная модель пишет черновик отклика, но только для вакансий выше порога.
6. **Telegram-бот** присылает карточку вакансии, черновик и кнопку «✅ Отклик отправлен» — нажатие помечает черновик отправленным в БД (переживает рестарт процесса).
7. Вы вставляете текст на Upwork и отправляете **вручную**.

> **Важно.** Ассистент никогда не отправляет отклики сам. Правила Upwork запрещают автоматическую подачу заявок, и публичного API для этого не существует. Инструмент экономит время на поиске и написании, но финальное действие всегда за человеком.

**Этот README — для разработчика** (установка, архитектура, деплой). Если вам нужно просто пользоваться уже запущенным ассистентом (что означают сообщения в Telegram, как посмотреть статистику, как настроить фильтры без программирования) — см. **[USER_GUIDE.md](USER_GUIDE.md)**.

## Стек

| Слой | Технология |
|---|---|
| HTTP API | FastAPI, Uvicorn |
| Конфигурация | Pydantic Settings |
| Сбор данных | Patchright (стелс-форк Playwright); DOM-фолбэк — Playwright-локаторы, без отдельной библиотеки парсинга |
| LLM | OpenRouter (модели GPT-5), прямой HTTP через httpx |
| Telegram | aiogram 3 |
| Планировщик | APScheduler |
| Хранилище | SQLAlchemy 2 + aiosqlite, миграции Alembic |
| Качество | ruff, mypy, pytest |

## Требования

- Python 3.12+
- Аккаунт Upwork
- Ключ OpenRouter
- Telegram-бот и ваш user id
- Docker и Docker Compose (для контейнерного запуска)

## Подключение внешних сервисов

### OpenRouter (LLM)

Единый шлюз к моделям OpenAI, оплата по факту использования.

1. Зарегистрируйтесь на [openrouter.ai](https://openrouter.ai/).
2. Пополните баланс в разделе [Credits](https://openrouter.ai/credits).
3. Создайте ключ на [openrouter.ai/keys](https://openrouter.ai/keys).
4. Вставьте его в `.env`:

```ini
OPENROUTER_API_KEY=sk-or-v1-...
```

Модели задаются отдельно для двух задач, потому что скоринг вызывается для каждой вакансии, а генерация — только для прошедших порог:

```ini
OPENROUTER_SCORING_MODEL=openai/gpt-5-mini    # $0.25 / $2 за 1M токенов
OPENROUTER_PROPOSAL_MODEL=openai/gpt-5        # $1.25 / $10 за 1M токенов
OPENROUTER_DAILY_BUDGET_USD=2.0               # жёсткий дневной потолок
```

Более дешёвый вариант скоринга — `openai/gpt-5-nano` ($0.05 / $0.40). Актуальные цены и список моделей: [openrouter.ai/models](https://openrouter.ai/models). Документация API: [openrouter.ai/docs](https://openrouter.ai/docs).

### Telegram

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и следуйте инструкциям.
2. Скопируйте токен вида `1234567890:ABCdef...`.
3. Узнайте свой числовой id у [@userinfobot](https://t.me/userinfobot) командой `/start`.
4. Напишите своему боту `/start`, иначе он не сможет вам писать первым.

```ini
TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz
TELEGRAM_USER_ID=123456789
```

### Upwork

Логин и пароль нужны только для **разового** входа, который сохраняет сессию в профиль браузера. Дальше ассистент работает на сохранённых cookies.

```ini
UPWORK_EMAIL=you@example.com
UPWORK_PASSWORD=...
UPWORK_SEARCH_URLS=https://www.upwork.com/nx/search/jobs/?q=python&sort=recency
```

Поиски живут в БД и правятся через веб-панель (раздел «Поиски») — настройте фильтры прямо на сайте Upwork, скопируйте URL из адресной строки и вставьте в панель. `UPWORK_SEARCH_URLS` оставлен только для первого запуска: значение оттуда (несколько адресов разделяются `;`) один раз переносится в БД, если таблица поисков пуста, и больше не читается.

Если Cloudflare начнёт блокировать IP сервера, укажите прокси:

```ini
UPWORK_PROXY=http://user:pass@host:port
```

### Профиль фрилансера

Создайте `data/profile.md` со своим опытом, стеком, примерами работ и желаемым тоном общения. Этот текст подмешивается в промпт генерации — без него отклики получаются безликими.

```ini
FREELANCER_PROFILE_PATH=data/profile.md
```

## Запуск

### Локально

```bash
source .venv/Scripts/activate
python -m upwork_assistant
```

Проверка: `curl http://127.0.0.1:8077/health` → `{"status":"healthy","version":"0.1.0"}`

Порт по умолчанию — **8077**, а не 8000: 8000 на машине разработки уже занят другим сервисом. Меняется через `API_PORT` в `.env`.

### Веб-панель

`GET /` отдаёт самодостаточную HTML-страницу (`src/upwork_assistant/api/static/index.html`, без сборки/npm/CDN) — статистика, список вакансий с черновиками, управление фильтрами и kill switch в браузере, поверх тех же REST-эндпоинтов, что описаны ниже. Открыть: `http://127.0.0.1:8077/`. Это основной интерфейс для конечного пользователя — подробности в [USER_GUIDE.md](USER_GUIDE.md); curl-примеры в этом README остаются рабочим способом того же самого для скриптов/автоматизации.

### Kill switch

Ручная остановка/возобновление опроса через REST — на случай, когда автоматика (circuit breaker) ещё не сработала, но проблему уже видно (например, подозрительная активность в аккаунте Upwork), и ждать три подряд неудачных цикла нельзя. То же самое доступно кнопками на веб-панели (см. выше) — команды ниже нужны, если панель недоступна или вы автоматизируете это скриптом.

```bash
curl http://127.0.0.1:8077/admin/status              # scheduled, circuit_open, consecutive_failures
curl -X POST http://127.0.0.1:8077/admin/pause        # снять запланированный цикл опроса
curl -X POST http://127.0.0.1:8077/admin/resume       # сбросить circuit breaker и поставить цикл немедленно
```

`resume` сбрасывает счётчик подряд неудачных циклов, а не только планирует следующий — иначе после срабатывания circuit breaker он тут же снова упёрся бы в тот же открытый breaker без единой реальной попытки (это реально ловили на боевом VPS 2026-09-08 и починили).

`pause` не прерывает уже выполняющийся цикл опроса — только снимает следующий запланированный. Эндпоинты без аутентификации: это приемлемо только для личного развёртывания за приватной сетью, без публичного доступа — не воспринимайте как реальную защиту.

### Docker

```bash
docker compose up -d --build
docker compose logs -f
curl http://127.0.0.1:8077/health
```

## Деплой

Пошаговая инструкция по выкатке на VPS через GitHub (клонирование, перенос секретов и профиля браузера, первый запуск, обновления, траблшутинг) — в [DEPLOY.md](DEPLOY.md). Ниже — краткая версия для локального/тестового запуска через Docker Compose.

1. `.env` должен лежать рядом с `docker-compose.yml` (см. «Подключение внешних сервисов» выше — там же переменные для kill switch и бюджета не нужны, они уже часть основного конфига).
2. Перед первым запуском на новой БД накатите миграции Alembic — один раз:

   ```bash
   docker compose run --rm assistant alembic upgrade head
   ```

   (или `docker compose exec assistant alembic upgrade head`, если контейнер уже поднят).
3. Соберите и поднимите контейнер:

   ```bash
   docker compose up -d --build
   curl http://127.0.0.1:8077/health
   ```

`UPWORK_HEADLESS=False` (значение по умолчанию) требует X-дисплея — `CMD` в `Dockerfile` уже оборачивает запуск в `xvfb-run`, это не случайность и не нужно убирать. `patchright install --with-deps chrome` в `Dockerfile` **не проверен на Linux** (проверялось только обнаружение системного Chrome на Windows) — если контейнер не сможет запустить браузер в рантайме, в `Dockerfile` рядом закомментирован fallback-блок с установкой `google-chrome-stable` из официального репозитория Google, используйте его.

## Структура

```
work_assistant/
├── src/upwork_assistant/
│   ├── __main__.py        # точка входа
│   ├── config.py          # настройки из .env
│   ├── container.py       # сборка и владение зависимостями
│   ├── app.py             # фабрика FastAPI
│   ├── logging.py         # логирование
│   ├── domain/            # модели и правила, независимые от площадки
│   ├── ports/             # интерфейсы: источник вакансий, LLM, нотификатор, репозитории
│   ├── adapters/          # реализации портов: upwork/, llm/, telegram/, db/
│   ├── services/          # сценарии: сбор, фильтрация, скоринг, генерация
│   ├── scheduler/         # APScheduler
│   ├── api/               # роутеры и DTO
│   └── tools/             # разовые команды (ассистированный вход)
├── tests/
├── migrations/            # Alembic
├── data/                  # БД, профиль браузера, профиль фрилансера (в git не хранится)
└── logs/
```

Направление зависимостей: `api / telegram / scheduler` → `services` → `ports` + `domain`. Адаптеры реализуют порты и известны только контейнеру; доменный слой не знает ни про Upwork, ни про базу.

## Статус

Проект в разработке. Готово:
- каркас, конфигурация, логирование, контейнер зависимостей, `/health`;
- слой хранения (таблицы SQLAlchemy, репозитории, `UnitOfWork`, миграции Alembic);
- слой LLM (клиент OpenRouter с ретраями и учётом стоимости, `scoring_service`, `proposal_service`, таблица `llm_usage`);
- сбор вакансий с Upwork (Patchright, ассистированный вход `tools.login`, извлечение вакансий из embedded Nuxt-состояния страницы поиска — см. `adapters/upwork/ssr_state.py`, маппер выверен по реальным захваченным данным в `tests/fixtures/upwork/`);
- пайплайн опроса (сбор → дедуп → фильтр → скоринг → черновик, одна транзакция на вакансию), Telegram-бот, планировщик APScheduler, REST-эндпоинты фильтров/вакансий/черновиков/статистики;
- **пагинация поиска**: `UpworkJobSource` листает до `UPWORK_MAX_PAGES_PER_SEARCH` (по умолчанию 3) страниц выдачи на каждый сохранённый поиск за цикл, а не только первые 10 вакансий;
- **`UpworkJobFacts` сохраняются в БД** (таблица `upwork_job_facts`, миграция `0003`) — сырой payload источника архивируется по каждой вакансии для реплея маппера при дрейфе схемы, а не отбрасывается;
- **DOM-фолбэк реализован предметно** (`adapters/upwork/dom_fallback.py`): при сбое извлечения embedded-состояния парсит реальную разметку страницы поиска (`[data-test="JobTile"]` и вложенные селекторы, сняты вручную 2026-09-07) в ту же схему, что и основной путь, — включая тип оплаты/бюджет, уровень опыта, конкуренцию по откликам и навыки;
- **лимит загрузок страниц в час** (`MAX_PAGE_LOADS_PER_HOUR`) реально применяется: и планировщик, и `UpworkJobSource` считают загрузки через один общий экземпляр `PollingPolicy` (см. `container.py`) — настройка больше не мёртвый конфиг. При исчерпании лимита середина цикла опроса не падает с ошибкой, а тихо возвращает то, что успела собрать;
- **circuit breaker**: 3 подряд неудачных цикла опроса (настраивается через `circuit_breaker_threshold`) останавливают дальнейший опрос и шлют алерт в Telegram — нужно ручное вмешательство (`POST /admin/resume` после устранения причины);
- **kill switch** — `GET /admin/status`, `POST /admin/pause`, `POST /admin/resume` (см. раздел «Kill switch» выше);
- **веб-панель** (`GET /`, `src/upwork_assistant/api/static/index.html`) — статистика, список вакансий с раскрывающимися черновиками (копирование в один клик, отметка «отправлено»), управление пресетами фильтров через форму (без ручного JSON) и kill switch кнопками — поверх существующих REST-эндпоинтов, без изменения их поведения; см. «Веб-панель» выше и [USER_GUIDE.md](USER_GUIDE.md);
- **дневной бюджет на LLM** (`OPENROUTER_DAILY_BUDGET_USD`) реально ограничивает расходы: перед генерацией черновика пайплайн проверяет сумму трат за сегодня (`llm_usage.total_cost_since`) и, если бюджет исчерпан, пропускает генерацию с алертом вместо вызова модели. **Важно:** бюджет ограничивает только генерацию отклика — скоринг вакансий им не ограничен и продолжает работать даже при исчерпанном бюджете (так и задумано: скоринг дешевле генерации на порядок, и без него нечем было бы даже понять, что вакансия того стоит).
- **поиски в БД** — адреса сохранённых поисков хранятся в таблице `search_queries` и правятся в веб-панели без перезапуска; `UPWORK_SEARCH_URLS` из `.env` переносится однократно при первом старте;

**Известные ограничения:**
- на проверке 2026-09-07 `UPWORK_HEADLESS=True` упирался в челлендж Cloudflare даже с валидным залогиненным профилем; `False` (headful) проходит стабильно с домашнего IP. Пока обход не найден, конфиг по умолчанию — headful. На сервере это значит: нужен виртуальный дисплей (Xvfb) для запуска браузера без физического монитора — `Dockerfile` уже это учитывает (см. «Деплой»);
- на реальном VPS (DigitalOcean, проверка 2026-09-08) даже headful-режим с валидным профилем может упираться в таймаут при заходе на upwork.com — инфраструктура при этом полностью рабочая (Chrome запускается, `google.com` открывается нормально), просто IP дата-центра, вероятно, попадает под более жёсткую проверку Cloudflare, чем домашний IP. Митигация — резидентный/мобильный прокси через уже существующий `UPWORK_PROXY`, либо полагаться на circuit breaker и kill switch. Подробности и диагностика — в [DEPLOY.md](DEPLOY.md#траблшутинг);
- `Connects`/`entry_cost` всегда `0` — эти данные приходят только со страницы конкретной вакансии, а не со страницы поиска, откуда собирается список; отдельный сбор деталей вакансии не реализован;
- DOM-фолбэк восстанавливает меньше, чем основной путь: точную дату публикации (только относительная фраза вида "Posted 2 hours ago" → грубое приближение), полное описание (только обрезанный сниппет) и весь список навыков (Upwork прячет часть за "+N" в самой вёрстке) — ожидаемо для аварийного пути, не баг;
- эндпоинты `/admin/*` не защищены аутентификацией — приемлемо только для личного развёртывания без публичного доступа, не переоценивайте это как настоящую защиту.
